# Prerequisites

* **Helm 4** (Helm 3 is not supported: rendering fails with a clear message).
* Kubernetes >=1.30.0-0.
* `kubectl` configured for the target cluster.

Install the tools with `make install-deps` (see [REQUIREMENTS.md](../../REQUIREMENTS.md)).

# Installing the chart

```bash
# Check what will be created
helm upgrade --install myhealthcheck charts/myhealthcheck \
  -n myhealthcheck --create-namespace --dry-run=server

# Install / upgrade
helm upgrade --install myhealthcheck charts/myhealthcheck \
  -n myhealthcheck --create-namespace -f my-values.yaml

# Smoke test (calls /health/ready)
helm test myhealthcheck -n myhealthcheck
```

# Examples

Only some namespaces, every port, least-privilege RBAC (Role per namespace):

```yaml
rbac:
  clusterWide: false
config:
  discovery:
    namespaces: [shop, payments]
    ports: ["*"]
```

Every namespace except the system ones and the `*-dev` ones:

```yaml
config:
  discovery:
    namespaces: []
    excludeNamespaces: [kube-system, kube-public, kube-node-lease, "*-dev"]
```

Static targets outside the cluster + webhook alerts + persistent history:

```yaml
config:
  healthEndpoints:
    - https://api.example.com/health
    - http:10.0.0.5:8080/status
  targets:
    - name: legacy-erp
      url: http://erp.internal:8080
      paths: [/live, /ready]
      match: all
  alerting:
    existingSecret: myhealthcheck-alerts   # key: webhook-url
persistence:
  enabled: true
```

# Service annotations

Discovered `Service` objects can customize their checks:

| Annotation | Example | Meaning |
|---|---|---|
| `myhealthcheck.io/enabled` | `"false"` | Skip this service (`"true"` opts in when `requireAnnotation=true`) |
| `myhealthcheck.io/port` | `http` or `3000` | Check only this port, even if it is not in `config.discovery.ports` |
| `myhealthcheck.io/paths` | `/livez,/readyz` | Custom paths instead of the default ones |
| `myhealthcheck.io/match` | `all` | `any` (default) or `all` paths must answer |
| `myhealthcheck.io/scheme` | `https` | Scheme used to reach the service |
| `myhealthcheck.io/expected-status` | `200,204` | Accepted status codes |
| `myhealthcheck.io/expected-body` | `ok` | Substring required in the body |

# Observability

* **Metrics**: `GET /metrics`. Enable `serviceMonitor.enabled` (Prometheus Operator) and
  `prometheusRule.enabled` for ready-made alerts.
* **Logs**: JSON on stdout. Any collector (Grafana Alloy, Promtail, Fluent Bit) can ship them to Loki;
  Loki derives `service_name` from the `app.kubernetes.io/name` label.
* **Traces**: set `config.tracing.enabled=true` and `config.tracing.endpoint` to an OTLP/HTTP
  endpoint (Alloy, OpenTelemetry Collector, Tempo or Jaeger).
* **Dashboard**: `grafanaDashboard.enabled=true` creates a ConfigMap for the Grafana sidecar
  (`grafana_dashboard: "1"` label). It uses datasource variables, so it works with any
  Prometheus/Loki/Tempo datasource names.

See [docs/observability.md](../../docs/observability.md).

# Uninstalling the chart

```bash
helm uninstall myhealthcheck -n myhealthcheck
```

The PVC (if `persistence.enabled`) is removed too unless `persistence.existingClaim` was used.

# Upgrading from chart 0.x

Chart 1.0.0 is a breaking release:

* The chart was renamed from `helm-health-check` to `myhealthcheck` and moved to `charts/myhealthcheck`.
* Probes now use `/health/live` and `/health/ready` instead of `ps | grep`.
* RBAC is read-only (`get/list/watch`), controlled by `rbac.*` and the ClusterRole name is unique per release namespace.
* The container runs as non-root with a read-only root filesystem.
* All settings live under `config.*` (rendered into a ConfigMap).

Uninstall the old release and install the new one.
